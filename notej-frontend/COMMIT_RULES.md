# ✅ 커밋 메시지 작성 규칙 (NoteJ 프로젝트)

이 문서는 Vue 3 + Vuetify 프로젝트의 깔끔하고 일관된 Git 커밋 메시지를 위해 작성되었습니다.  
혼자 개발할 때도 **기록을 잘 남기면**, 추후 리팩토링, 버그 수정, 배포 준비 등에 큰 도움이 됩니다.

---

## 1. 기본 형식

```
<type>(scope): <변경한 내용>
```

- `type`: 작업의 성격을 나타냅니다 (필수)
- `scope`: 영향을 받은 컴포넌트나 파일 이름 등 (선택)
- `내용`: 간결하고 명확하게 작성

---

## 2. 커밋 타입 목록

| 타입 | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서, 주석 수정 |
| `style` | 코드 포맷, 공백, 세미콜론 등 (로직 변화 없음) |
| `refactor` | 코드 리팩토링 (기능 변화 없음) |
| `test` | 테스트 코드 추가 또는 수정 |
| `chore` | 설정, 빌드, 의존성 등 기타 작업 |

---

## 3. 예시

```
feat(navbar): 다크모드 토글 버튼 추가
fix(router): 라우팅 오류 수정
style(theme): 배경 색상 조정
refactor(app): 레이아웃 구조 정리
docs(readme): 프로젝트 소개 문구 추가
chore: Vuetify 설정 및 기본 플러그인 구성
```

---

## 4. 커밋 메시지 팁

- 내용은 **한글 또는 영어 모두 가능** (일관성만 유지)
- 첫 문장은 **명령형**으로, 간결하게
- 너무 긴 설명은 커밋 본문에 추가 가능 (혼자 작업 시 생략 가능)

---

## 5. 권장 워크플로우

1. 작업 전에 항상 `git pull`
2. 기능 단위로 브랜치 분기 (`dev-frontend-vue-init` 등)
3. 커밋 → `git commit -m "feat: ..." `
4. 작업 완료 후 `main` 또는 `dev` 브랜치에 병합
